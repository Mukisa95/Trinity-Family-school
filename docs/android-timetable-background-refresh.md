# Timetable background refresh reliability

Trinity Live 1.17 / version code 19 repairs the timetable widget and persistent notification refresh chain. It preserves timetable selections, the compact card layouts, navigation controls, lesson reminders and the existing progress option.

The previous implementation used one `setAndAllowWhileIdle` alarm for both lesson boundaries and minute progress changes. On the Pixel, that alarm had a one-hour delivery window even though accurate alarm access was already allowed. A rendering/read exception could also end the chain without scheduling another refresh. Widget periodic updates were disabled, and the timetable receiver did not listen for application replacement. Android's [alarm documentation](https://developer.android.com/develop/background-work/services/alarms) describes how inexact alarms and idle restrictions delay delivery.

The update uses independent pending intents: an exact lesson/access-expiry alarm when Alarms & reminders access is allowed, and a non-wakeup minute alarm for visible countdowns/progress while the phone is interactive. Inexact timing remains supported when access is denied. Screen-on, unlock and system minute broadcasts refresh a living process; application startup/resume, boot, clock/timezone changes, application replacement and accuracy-permission grants rebuild the schedule.

On the actual Pixel Launcher, a `Chronometer` inside the scrolling collection could stop after a row was detached/reused, most visibly in the first row. The [Android Chronometer implementation](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/core/java/android/widget/Chronometer.java) stops on detach and uses window visibility to resume; the device observation motivated avoiding that dependency in collection rows. Widget badges now show remaining hours/minutes, rounded up, and recompute from the current clock on each visual refresh. Upcoming countdowns schedule that refresh even when progress bars are hidden. Notification countdowns outside the collection retain their native timer. Lesson boundaries remain separate from minute display updates.

A unique local WorkManager task periodically checks the cached timetable and repairs a lost schedule. It needs no internet connection. Both widget providers also restore Android's 30-minute host update fallback. Neither fallback promises exact timing under Doze; the lesson alarm supplies the timely boundary update when accurate access is allowed. See Android's [widget refresh guidance](https://developer.android.com/develop/ui/views/appwidgets/advanced) and [periodic work guidance](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work).

Recovery is armed before any display is rendered. A notification render error cannot block widgets, or vice versa. A failed cache read schedules another attempt without changing appearance preferences. Missing, expired or unauthorised cached access still clears the displays; disabling the card without any widgets cancels background recovery. Each update recomputes from the current school-zone clock rather than advancing an old frame.

**Timetable card settings → Allow accurate timetable timing** opens Android's existing Alarms & reminders permission screen. No battery exemption or new always-running service is required. Android can still defer fallback work or prevent execution when a user force-stops/restricts an application; no indefinite background execution is promised.

Validation: the signed release build passed, as did 56 native unit tests, 28 focused web/bridge/push tests and 9 final release/download tests. Sixteen Pixel checks covered independent alarms, idle scheduling, recovery after a corrupt test cache, a real recovery worker repairing a cancelled schedule, upcoming countdowns with progress hidden, installed system receiver resolution, shortcut identity, notification icons, push, timetable preference preservation, all widget sizes, compact scrolling and accessible controls. A separate real alarm check passed with the screen off and the Pixel forced into deep Doze: a boundary alarm fired in about 10 seconds, refreshed the real cached timetable without an activity, and scheduled its next boundary while leaving the screen asleep. Normal idle mode and wake state were restored afterward. No actual school records were changed; the corrupt file was a separate test-only cache.

On the real home-screen widget, both countdowns changed across a minute boundary without opening the app (`3h 5m` → `3h 4m` and `2h 5m` → `2h 4m`). Next-period and Return to live controls also worked on the installed widget; both rows were restored to live afterward. The notification card remains enabled. The instrumentation helper was removed after testing.
