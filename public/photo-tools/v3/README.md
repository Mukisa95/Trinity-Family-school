# Portrait editor tools, version 3

The saved school photo remains an opaque 500 x 500 JPEG, at most 180 KiB.
Tight, Standard and Headroom presets change head framing within that square.
They use the measured crown where available and retain upper shoulders, subject
to source bounds and the existing minimum 500-pixel source crop. Circle and
Square are preview guides; neither changes the saved dimensions.

The editor groups Crop, Enhance, Filters and Background controls around a stable
preview. Quality appears only when a detected framing/detail or image-quality
issue exists, and never changes the crop viewport size. Review and saving use
the same prepared JPEG. Original comparison uses the untouched source crop.

Enhance adds contrast, shadows, highlights, saturation, tint, sharpness and
smoothing alongside brightness, warmth and Auto. Natural, Clean, Soft, Vivid,
Warm, Cool and B&W filters apply bounded pixel adjustments. Adjustments always
start from original pixels, never the previous preview.

Background removal refines the existing person mask using the untouched image's
luminance (guided filtering), anchors confident foreground/background, and
removes tiny isolated foreground specks while keeping nearby hair. Edge and
Feather controls adjust matte coverage and softness. White, Grey and Blue are
opaque background colours. This improves uncertain edges but cannot recover
hair or clothing missing from the model's mask. Inspect the preview before saving.
An absent subject or failed segmentation blocks saving until removal is turned
off or retried.

Guided filtering reference: He, Sun and Tang, *Guided Image Filtering*:
https://people.csail.mit.edu/kaiming/eccv10/index.html

`photo-worker.js` is generated by `node scripts/build-photo-tools.cjs`. Processing
and refinement run in a worker, with CPU fallback for adjustments. The immutable
v1 runtime/detector and v2 segmenter are reused; no new model dependency/download
is introduced. All versions share the preserved `trinity-photo-tools-v1` public
asset cache. Once cached successfully, a new worker can run offline. Photos are
never stored in this tools cache or sent to an external processing service.
Existing school record saving still requires the application's normal connection.

The v3 worker URL prevents an old cached v2 worker from losing new controls.
Keep published v1/v2 assets unchanged. Future processing changes must use a new
worker URL. Use another editor, JPEG import and native camera selection remain
available through the existing integration.
